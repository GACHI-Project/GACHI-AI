# 가정통신문 라벨링 기준 v3

## 입력과 정답 분리

- `input.originalText`: BE가 OCR 결과를 정제하고 페이지 순서대로 결합한 실제 AI 입력이다.
  오인식과 누락을 임의로 수정하지 않는다. 사람이 교정한 본문은 별도 `goldText`에 보관하며 입력에 넣지 않는다.
- `input.dateCandidates`: 실제 BE 추출 결과다. 후보 누락이나 잘못된 연도도 그대로 보관한다.
- `input.referenceDate`: 평가에서 고정한 업로드 기준일이다. 문서 발행일인 `documentDate`로 대체하지 않는다.
- `expected`: 사람이 원본을 대조한 정답이다. 후보 누락이나 현재 모델의 결과에 맞춰 날짜 정답을 바꾸지 않는다.
- 수동 후보와 기존 근거문만 있는 초안은 평가용 실제 입력이 아니다. 입력 없이 평가하면 오류로 종료한다.

## 일정과 날짜

- `deadline`: 제출, 신청, 납부 등 기한이 있는 구체적 행동.
- `schedule`: 실제 행사, 교육, 운영 일정.
- `reminder`: 날짜 없는 구체적이고 완료 가능한 행동 그룹.
- 발행일, 작성일, 서명란의 날짜는 실제 사건과 연결되지 않으면 일정으로 만들지 않는다.
- 시각 없는 날짜는 `YYYY-MM-DD`만 사용한다. 00:00 또는 23:59:59를 임의로 붙이지 않는다.
- 시각이 있으면 ISO datetime과 timezone을 사용한다. schedule은 시작 시각, deadline은 마감 시각이다.
- 행사 종료는 `endDatetime`, 접수 시작은 `periodStartDatetime`이다. 해당 없으면 null이다.
- 접수 기간은 마감 deadline 한 건이며 접수 시작을 별도 일정으로 만들지 않는다.
- 예: 9월 10일 10시부터 9월 28일 18시까지 접수라면 datetime은 9월 28일 18시,
  periodStartDatetime은 9월 10일 10시다.
- endDatetime은 시작보다 빠를 수 없고 periodStartDatetime은 마감보다 늦을 수 없다.
- reminder는 missing, 날짜 3개 필드 모두 null, needsUserConfirmation=false다.
- 원본 날짜 자체에 해결되지 않는 연도/요일 충돌이 있으면 ambiguous,
  날짜 3개 필드는 null, needsUserConfirmation=true로 둔다. 요일만으로 연도를 고치지 않는다.
- confirmed는 needsUserConfirmation=false다. 발행일 오류와 실제 사건 연도의 불확실성을 구분한다.

## 날짜 후보와 원본의 관계

원본 포함 모델은 후보가 누락되거나 틀려도 원본에서 명확한 날짜를 확인할 수 있다.
텍스트 전용 모델은 현재 후보 제약을 적용받는다. 두 입력 조건을 구분해서 평가한다.
정답의 실제 사건 날짜는 동일하게 유지하고, 후보 누락 때문에 모델이 놓친 사건은 오류로 기록한다.
selectedDateCandidateId는 BE 입력 연결 후 대응 후보가 유일할 때만 재연결한다.
선택 후보 ID 자체는 현재 정답 점수에 포함하지 않는다. 오래된 수동 후보의 인덱스를 재사용하지 않는다.

## 행동과 체크리스트

- 원문이 요구하는 구체적 준비, 작성, 서명, 제출 행동을 관련 항목의 checklistItems에 넣는다.
- 기한 없이 요구된 행동은 reminder로 보존하며 발행일에 연결하지 않는다.
- 신청 자격, 금액, 방법, 정원, 선착순, 취소 조건은 관련 행동의 detail에 보존한다.
- 간주 동의를 별도의 서명/동의 행동으로 바꾸지 않는다.
- 일반 안전 권고, 기관 연락처, 제공 혜택, 임기 설명은 현재 할 일로 만들지 않는다.
- 미래의 발병이나 추후 선발처럼 조건 충족 여부가 정해지지 않은 일반 대응 안내는 현재 행동과 구분한다.
  현재 신청 대상의 자격 조건은 관련 신청 행동에 보존한다. 조건문이라는 이유만으로 모든 신청을 제외하지 않는다.
- 명시적인 '첨부 안내장을 자녀와 함께 읽어 주세요'는 완료 가능한 행동이다.
  안전 수칙 소개나 영상 링크만으로 읽기/시청 과제를 만들지 않는다.
- checklistItems 누락은 미라벨링이며 채점 제외다. []는 할 일이 없다는 명시적인 정답이다.

## 체크리스트 채점용 표현

기본은 공백/기호 정규화 후 content 일치다. 뜻이 같은 표현을 허용하려면
`acceptedContents` 또는 `contentPatterns` 배열을 정답에 명시한다. contentPatterns는 모두 만족해야 한다.
금액/방법 등 중요한 조건은 `detailPatterns` 배열로 지정할 수 있다. 이 역시 모두 만족해야 한다.
패턴이 없고 detail이 있으면 정규화 문자열 일치로 비교한다. detail이 없으면 상세 조건은 미평가다.
유사도만으로 의미 일치를 단정하지 않는다. 제목/요약과 패턴의 적절성은 수동 검수 대상이다.

## 검수 상태

`metadata.annotationStatus`는 draft 또는 reviewed다. 이전만 마친 라벨은 draft를 유지한다.
모델 confidence는 정답의 확신도가 아니므로 완전 일치로 채점하지 않는다.
labelVersion과 변경 이유를 기록한다. 기존 pilot 이전 및 검수 대기 항목은
`newsletter-pilot-migration.md`에 정리한다.
